# Skill-Forge

一组可复用的个人 Skills。

## Skills

| Skill | 触发规则 | 用途 |
| :--- | :--- | :--- |
| [`explain`](#explain) | 仅显式触发（`$explain` 或 `/explain`） | 按用户当前理解程度，解释术语、概念、机制与已有方法或体系 |
| [`grill-me`](#grill-me) | 仅显式触发（`$grill-me` 或 `/grill-me`） | 通过连续追问，打磨尚未成熟的想法与决策 |
| [`handoff`](#handoff) | 仅显式触发（`$handoff`） | 为下一会话 Agent 创建交接文档 |
| [`read-paper`](#read-paper) | 仅显式触发（`$read-paper` 或 `/read-paper`） | 对论文进行快速概览、深入解读、代码解析 |

### `explain`

一个通用解释助手。

它先直接说明概念是什么，再根据你表现出的知识水平调整解释深度。
在面对宽泛概念时，只展开核心定义、最小框架和关键边界。
它用于解释已有术语、概念、机制、方法或体系，不负责定制方案的设计、评审或执行。

使用示例：

```text
$explain ${术语、概念、机制、方法或体系}
$explain ${多个相近术语之间的区别}
```

### `grill-me`

一个想法与决策打磨助手。

> 访谈期间只分析和确认，不执行方案或修改外部状态。

它通过连续追问暴露隐藏假设、薄弱环节、依赖、约束和取舍。
每轮只追问一个会实质影响结果的最高优先级问题。
必要性不明显时，会简要说明原因；涉及决策时，会给出建议和取舍。
若后续回答与已有结论冲突，它会回到相关分支重新确认。
当所有关键分支都已明确后，它会总结双方共识并请求确认；
只有得到你的明确确认，访谈才会结束。除非访谈结束后你另行要求，否则不会创建单独的交付物。

使用示例：

```text
/grill-me ${你当前尚未成熟或不够明确的想法}
```

### `handoff`

一个把当前会话压缩为交接文档的助手。

它把文档保存到当前工作区，文件名为 `handoff-{topic}.md`；其中 `topic` 由模型根据下一会话重点生成。

使用示例：

```text
$handoff
```

### `read-paper`

一个论文助手。

> 每次只处理一篇论文，不用于多论文比较。

主要模式：

| 模式 | 适用场景 | 输出 |
| -------- | ------------------- | ------------------------------- |
| **快速概览** | 判断论文是否与你的问题、方向或场景相关 | 基于摘要、结论和关键证据，概述匹配点、缺口、风险及下一步建议 |
| **深度解读** | 系统理解研究问题、方法、实验与结论 | 基于全文分析贡献、方法、证据设计、结果、局限和未来方向 |
| **代码解析** | 理解论文方法如何对应官方或复现代码 | 解析仓库结构、执行流程、论文概念与代码位置，并提供最小使用示例 |
| **绘制流程图** | 梳理论文中的系统、算法流程或概念关系 | 按用户指定的内容和范围绘制 Mermaid 图；有原图时忠实还原，无原图时注明为自绘 |

也可以针对论文中的某个公式、图表或具体问题进行定向解读。

使用示例：

```text
$read-paper ${论文名称/DOI/URL/PDF/...} # 默认快速概览
$read-paper 深度解读
$read-paper 代码解析
$read-paper 绘制算法流程图和实验流程图
```
